Async Callback Queue Processor

This document explains the Meta frontend interview problem: implement a queue that handles async callbacks with limited concurrency and configurable queue ordering.

Problem summary

The goal is to implement a class QueueCallbacks with the following features:

  • Allow up to a configured number of asynchronous callbacks to run in parallel.
  • If more callbacks arrive than the concurrency limit allows, queue them until slots become available.
  • If the pending queue is full, drop or reject additional callbacks.
  • By default, process queued callbacks in FIFO order.
  • If the constructor receives "LIFO", process queued callbacks in LIFO order.

Documentation

This file contains a small demo and reference implementation of a configurable async callback/task queue.

Purpose: limit concurrent async executions and control how additional tasks are queued and processed.

Key concepts

  • concurrentLimit / maxActive: how many tasks may run in parallel.
  • queueLimit / maxQueueSize: how many tasks may wait in the pending queue.
  • order: FIFO (default) or LIFO ordering for selecting the next queued task.

Public API

  • new QueueCallbacks(order, concurrentLimit, queueLimit) — create an instance.
  • instance.process(callback) — submit a callback (a function that returns a Promise). If there are available slots, it starts immediately; otherwise it is queued (or dropped if the queue is full).
  • _log(message) — internal helper used by the demo to print status.

Example

// Create a queue that runs up to 3 tasks concurrently, allows 5 queued tasks
const q = new QueueCallbacks('FIFO', 3, 5);

// Submit a task (task should be a function that returns a Promise)
q.process(() => fetch('/api/data'));

// You can submit many tasks; the queue enforces concurrency and capacity limits.

Behavior notes

  • Tasks are expected to be functions returning a Promise (e.g., network calls, timers).
  • The implementation does not change the return value of the task; it only starts and awaits it.
  • When a running task finishes (resolve or reject), a slot is freed and the next queued task (if any) is started.

Step-by-step explanation

  1. When process(callback) is called and fewer than the configured concurrent limit callbacks are currently running, execute the callback immediately.
  2. If the concurrent limit is reached, add the callback to the queue instead of executing it.
  3. If the queue already contains the configured queue limit of items, ignore the new callback and do not enqueue it.
  4. When a running callback finishes, reduce the active count and then try to execute the next callback from the queue.
  5. The next callback is selected using FIFO or LIFO, depending on the constructor argument.

In other words, the queue is only used when the concurrency limit has been reached. Once a callback finishes, queued callbacks are promoted to execution while still respecting the configured concurrent task limit.

Implementation details

The implementation uses three main concepts:

  • activeCount: how many async callbacks are currently running.
  • queue: a list of pending callbacks waiting for a free slot.
  • order: whether queued callbacks use FIFO or LIFO ordering.
  • maxActive and maxQueueSize: configured limits for concurrency and queue capacity. 
class QueueCallbacks {
  constructor(order = 'FIFO', concurrentLimit = 2, queueLimit = 6) {
    this.order = order === 'LIFO' ? 'LIFO' : 'FIFO';
    this.queue = [];
    this.activeCount = 0;
    this.maxActive = concurrentLimit;
    this.maxQueueSize = queueLimit;
  }

  async process(callback) {
    // If there is room, execute immediately.
    if (this.activeCount < this.maxActive) {
      this.activeCount += 1;
      try {
        await callback();
      } finally {
        this.activeCount -= 1;
        this._processNext();
      }
      return;
    }

    // If concurrency limit is reached, queue the callback if the queue is not full.
    if (this.queue.length < this.maxQueueSize) {
      this.queue.push(callback);
    }
    // If the queue is full, discard the callback.
  }

  _processNext() {
    if (this.activeCount >= this.maxActive || this.queue.length === 0) return;

    const nextCallback = this.order === 'LIFO'
      ? this.queue.pop()
      : this.queue.shift();

    if (nextCallback) {
      this.process(nextCallback);
    }
  }
}

How the implementation satisfies the prompt

Each rule is handled explicitly:

  • Configurable running callbacks: managed by activeCount and maxActive.
  • Queueing when concurrency limit is reached: handled by the else branch in process().
  • Max queue size: enforced by maxQueueSize before pushing onto queue.
  • Default FIFO order: set in the constructor when no or invalid argument is passed.
  • LIFO when requested: selected by the order field and pop() in _processNext().
