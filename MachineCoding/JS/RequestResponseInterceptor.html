Request/Response Interceptor — Documentation

Purpose: Build an Axios-style interceptor system on top of fetch that lets consumers register request and response interceptors which run in order before a request is sent and after a response is received.

API:

  • createClient() — returns a client instance with request, interceptors.request.use(onFulfilled, onRejected), and interceptors.response.use(onFulfilled, onRejected).
  • client.request(url, options) — runs registered request interceptors (in order) on the config, performs the fetch, then runs registered response interceptors (in order) on the result.

Behavior notes:

  • Request interceptors receive and must return a config object (e.g. to add headers/auth tokens).
  • Response interceptors receive and must return the response (or transformed data).
  • An interceptor's onRejected handler can be used to catch/recover from errors thrown earlier in the chain.
  • Interceptors should run in the order they were registered, chaining like a promise pipeline.

Usage example

const client = createClient();

client.interceptors.request.use((config) => {
  config.headers = { ...config.headers, Authorization: 'Bearer token' };
  return config;
});

client.interceptors.response.use((response) => {
  console.log('Response received:', response.status);
  return response;
});

client.request('/api/data').then((res) => console.log(res));
