MemoizeFunction

Implement memoize(fn) so repeated calls with the same serialized arguments reuse the earlier result instead of invoking fn again.

Problem Summary

  • Accept a function and return a wrapper that can cache its results.
  • Serialize each call's arguments to form a cache key.
  • Return the saved result when the key is present, including falsey results.
  • On a cache miss, call the original function with the current this value and arguments, then store and return the result.
  • The example memoizes factorial and calls it twice with 0.

Approach (Step By Step)

  • Create cache state: memoize creates a Map that the returned wrapper retains through a closure.
  • Build the key: JSON.stringify(args) converts the argument array to a string.
  • Check membership: cache.has(key) distinguishes a stored falsey result from a missing entry.
  • Return or compute: a hit returns the stored value; a miss invokes fn.apply(this, args), saves its result, and returns it.
  • Factorial behavior: recursion calls factorial directly, so recursive subproblems do not pass through the memoized wrapper.

Dry Run and Caveats

memoizedFactorial(0)

1. args is [0], so JSON.stringify(args) produces the key '[0]'.
2. The key is missing; factorial(0) reaches its base case and returns 1.
3. The wrapper stores 1 under '[0]' and returns it.
4. The second call creates '[0]' again; cache.has(key) is true, so it returns 1
   without calling factorial a second time.

The Map membership check handles falsey results correctly, but JSON-string keys have limitations: values such as undefined, functions, and symbols in arrays serialize as null, so distinct argument lists can collide. Circular values and BigInt arguments also make JSON.stringify throw. The cache key does not include this, so calls with the same arguments but different receivers can share a result even if fn depends on this.

Complexity

  • Each lookup first serializes the arguments, taking time proportional to their serialized size; Map lookup is typically O(1) on average.
  • On a cache miss, add the wrapped function's cost. For positive n, this recursive factorial takes O(n) time and O(n) call-stack space.
  • Space used by the cache grows with the number and size of distinct serialized keys and their results.
