Compare sequential vs parallel async execution

This example compares two ways to run async work: series and parallel. It explains how the async/await wrapper works and why the returned value is logged after each task completes.

How it works

The evaluate helper is declared as async, so it always returns a Promise. Inside it, await fn() pauses the wrapper until the provided function resolves, then logs the result.

Important: async makes the wrapper asynchronous, but it does not make a synchronous function automatically run in parallel.

Series vs parallel

series waits for A(1) to complete before starting B(2). Total time is roughly 3 seconds.

parallel starts both promises before awaiting them. It then waits for both to resolve, so total time is roughly 2 seconds.

Example code

const evaluate = async (fn, label) => {
  const startTime = performance.now();
  console.log(`Executing ${label} task starts`);
  const result = await fn();
  const endTime = performance.now();
  console.log(`Task ${label} finished in ${Number.parseFloat(endTime - startTime)} milliseconds with sum ${result}`);
};

const wait = (time) => new Promise((resolve) => setTimeout(() => resolve(time), time * 1000));

const A = (time) => wait(time);
const B = (time) => wait(time);

const series = async () => {
  const time1 = await A(1);
  const time2 = await B(2);
  return time1 + time2;
};

const parallel = async () => {
  const time1 = A(1);
  const time2 = B(2);
  const a = await time1;
  const b = await time2;
  return a + b;
};

evaluate(series, 'sequence');
evaluate(parallel, 'parallel');

What you should see

The console should log the two tasks separately, each showing elapsed time and the sum result. The parallel task completes faster because both timers are started before awaiting either one.
